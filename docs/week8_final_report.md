## 1. Problem and final outcome

The system receives multiple syllabi on a topic, including a new syllabus for
an additional course, and a student's academic identity (for example, “third
year student, computer science program”). It identifies which electives the
student can enrol in and recommends the best eligible option.

The final repository contains a working browser application at `/ui/`, a
versioned FastAPI service at `/v1`, a partner integration contract, official
programme-structure data, explainable eligibility checks, and the earlier
administrative NLP component. The advisor does not enrol the student: it
provides a cited recommendation and a coordinator review step.

The browser experience also works from a fresh checkout before optional
gitignored model artefacts are trained. In that case the HTTP component uses a
clearly labelled deterministic demo fallback over the verified service
catalogue and knowledge base; the trained-model path remains available for
full evaluation and deployment.

## 3. Product walkthrough

1. Open `/ui/` and select **Elective advisor**.
2. Keep the default identity or enter a supported programme and semester.
3. Load **Artificial intelligence** sample syllabi.
4. Click **Find my elective**.
5. Review the recommendation, confidence, every course decision, rule type,
   source citation, overlap warning, and enrolment guidance.
6. Open **Partner integration** to demonstrate syllabus and student-record
   calls through the same contracts used by external components.
7. Open **Ask the copilot** to demonstrate the Week 6 administrative NLP flow.

## 5. Testing and release gate

Run from the repository root:

```bash
uv sync
uv run pytest -q
uv run python -m nlp.pipeline.evaluate_week7
```

The test suite covers dataset checks, NLP components, API validation, file
parsing, partner failure reporting, eligibility rules, explainability,
responsible-AI counterfactuals, and UI/API smoke checks. The application is
ready for the final demonstration when the full suite and the Week 7
evaluation exit successfully.

## 6. Known limitations and next steps

- The catalogue is for the MPSTME 2026 structures represented in the
  repository; it must be rebuilt and reviewed for a new academic year.
- Demo syllabi are illustrative and must be replaced with approved syllabi in
  production.
- English identity text and the covered programmes are the supported scope.
  Unknown programmes and missing academic information abstain or request
  review rather than being guessed.
- Final registration remains with the programme coordinator, including
  capacity, timetable, backlog, and new-course approval checks.
